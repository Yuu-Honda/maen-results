## 必須修正（Blocking）

### workflow.js の `illustrate()` — ステージ③で根拠バッジ（`.wf-ref`）が不透明度0になり読めなくなる

- 該当: `workflow.js` の `illustrate` 関数内
  ```js
  refs.forEach(node => { node.style.opacity = String(phase(amounts[2], .65, 1)); });
  ```
  および `select()` 用の段位切替しきい値 `Math.floor(p * 4)`（p=.5でpane2=ステージ③が選択される）、ボタン停止位置 `stops = [.06, .34, .62, .92]`（ステージ③のstop=.62）。

- **問題**: `amounts[2] = phase(p, .51, .72)` であり、`.wf-ref` の不透明度は `phase(amounts[2], .65, 1)` で決まる。
  - ③の「③ 記録を添える」ナビボタンをクリックすると `p = .62` にジャンプする → `amounts[2] ≈ .524` → `phase(.524, .65, 1)` は負値 → クランプされ **opacity: 0**。
  - 通常のスクロールでも、ステージ③が `select()` により「現在のステージ」として可視化される境界 `p ≈ .5` の直後でも同様に `amounts[2] ≈ 0` 付近となり、opacity 0 の状態が続く。
  - 結果として、HTML上は `条件Y: 参照あり：名称の対応のみ` / `条件X・Z: 対応未解決：この条件も保持` という**この図の中核的な教育内容**（名称対応の暫定性・未解決の保持）が、pane自体は「表示中」（`aria-hidden="false"`）であるにもかかわらず**視覚的に消えている**状態でユーザーに提示される。
  - 特にナビボタンでのジャンプは「止めて読む」という利用者への明示的な約束と矛盾する — ボタンで止まった瞬間に肝心のテキストが見えない。
  - スクリーンリーダー利用者にはテキストが読み上げられる一方、晴眼者には空白に見えるという**アクセシビリティ上の不整合**も生じる。

- **修正提案**: `stops[2]` を refs の可視化が完了する範囲（例: `.75`付近）に合わせる、または `phase(amounts[2], .65, 1)` のしきい値を `select()` の境界（p=.5）やボタン停止位置（.62）に揃えて再設計すること。両者のパラメータ間に数値的な整合性チェックを追加することを推奨します。

## 任意の改善点（Non-blocking / Observations）

1. **カードギャップの毎フレーム再計算**: `illustrate()` 内で `cards[1].offsetTop - cards[0].offsetTop` をスクロールのたびに再計算している。値は本来不変なので `measure()` 側でキャッシュしたほうが望ましい（パフォーマンスのみ、機能影響なし）。

2. **`window.scrollTo({behavior:'instant'})`**: `'instant'` は非標準値。多くのブラウザでは即時ジャンプとして扱われるが、将来的な互換性のため `'auto'` または標準化された値の使用を検討してもよい（非ブロッキング）。

3. **`amounts[3]`（ステージ④用の reveal 値）が `illustrate()` 内で未使用**: パネル④（未確認リスト）には対応する動的演出がなく、計算された値が捨てられている。意図通りであれば問題なし（デッドコードとしての軽微な無駄のみ）。

4. **MCF7細胞株・12時間条件のような実験文脈がこの図内に明記されていない**: 既存の科学文テキスト側で説明されている前提であれば問題ないが、この図単体を読む初学者にとっては「78条件」がどの細胞・時間の実験かが分からない。既存アセット側で担保されているか確認を推奨（Codex側の管轄の可能性あり、ブロッキングではない）。
